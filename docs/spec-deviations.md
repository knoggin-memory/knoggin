# Deviations from the spec

One line for every place where the build departed from the tech spec, with the reason.

- Engine, full-text index: the `tags` column holds a memory's plain tags only, not the `entity/`, `topic/` and `emotion/` label terms. At the reference commit recalld fills the FTS row from the stored record's `tags` (`src/derived_completion.rs` line 614, `fts.add(ns, *id, &record.summary, text.as_deref(), &tags)` with `tags` from `record.tags`). On a store in the native format, which every new data directory is, `POST /memories` goes through `single_store_versioned` and `store_api1::create` to the native writer, whose `NativeInsert` keeps the labels in their own fields and the plain tags in `InsertMemory.tags` (`src/storage/native_records.rs`: "Structured labels are persisted verbatim, never normalized into compatibility tags"). The merge of labels into tags in `handlers::create_memory` (`src/api/handlers.rs` lines 300 to 374) runs only for a store in the legacy format (`src/api/store_api1.rs` lines 54 to 63). The ranking fixture is the authority: with label terms 14 of the 40 queries came out in another order, without them all 40 match exactly.
- Engine, supersedes: a chain is walked through every successor (breadth first, 10 hops) and a cycle simply ends the walk, so a memory in a cycle can still be replaced by the newest member; recalld follows one successor and gives up on a cycle. The spec's "follow all of them" rule decides; no store made by Knoggin can hold a cycle.
- Engine, recall: a query vector of the wrong dimension or with a value that is not finite is treated as no vector (`degraded: model_unavailable`), since the engine has no error code for a host fault.
- Engine, context: a `topic` that is empty after trimming counts as no topic.
- Engine, recall trace: `suppressed` lists the candidates whose effective strength retrieval-induced forgetting lowered; recalld also listed neighbors that were not candidates.
- Engine, idempotency: `knoggin-core` builds the request-hash input (`store::request_hash_input`: name, zero byte, canonical JSON) but does not hash it; the host takes its SHA-256 with aws-lc-rs. The core may not depend on aws-lc-rs and the rules ban `sha2`, and a hand-written SHA-256 would be cryptography outside aws-lc-rs.
- Engine, signatures: `Store::create(id, model, now)` takes `now`, because the `default` namespace it makes needs a `created_at`.
- Engine, idempotency: an entry older than 24 hours counts as absent at lookup but is removed only once the operation has succeeded (with the bookkeeping change then), so that a failed write leaves the store unchanged.
- Engine, index rules: one more derived index, per namespace the `(created_at, id)` of every memory that is not a ghost. Automatic links and the duplicate report take their candidates from it and from the entity index instead of scanning the store; it is kept in place, rebuilt and compared by the property test like the others.
- Engine, saving: a vector passed to `store_memory` that is not valid for the store's model counts as one failed embedding (the memory is saved `Pending` with its failure count at 1, and the bookkeeping counter moves), as `apply_embedding` treats the same vector. Refusing the save instead would fail a valid memory over a fault of the host's embedder.
- Engine, list cursors: `knoggin-core` makes them base64url without padding (of `<millis>.<id>` for memories and `<count>.<tag>` for tags), so the host passes them through; a cursor that does not decode to one is `invalid_argument` on `cursor`.
- Engine, context: the topic is checked only by the recall that `context` runs, and an `invalid_argument` on that recall's `query` is reported on `topic`, the field the client sent.
- Engine, signatures: every write takes `ctx` and `now` as its last arguments, and so do `record_access`, `sweep`, `apply_embedding` (edge times), `on_open`, `export_page` (the header's `exportedAt`) and `import_record`, which also takes `OnConflict`; `ExportPage` holds `TransferRecord` values and the host writes each as one JSON line.
- Engine, access recording: `record_access` adds 1 to the bookkeeping counter only when it recorded at least one hit, so a call with only ghosts or unknown IDs does not trigger a snapshot.
- Testing, ranking fixture: recalld ran with `[graph] auto_link_threshold = 0.95` and `max_auto_links`, `max_entity_links`, `max_temporal_links` = 1. With its defaults every memory saved within an hour got 20 or more temporal links, every degree was at least 35, the fan was 0, and spreading activation and the connection bonus never acted. Ranking does not read these settings; they only decide which edges recalld makes, and the fixture stores recalld's edges as they are.
- Testing, ranking fixture: both supersedes chains are linear, because recalld refuses a second successor for one memory. The multi-successor rule is covered by unit tests only.
- Testing, ranking fixture: access counts come from `recalld ui`'s history totals, because recalld's REST memory route has none; edges and counts were read after the queries (checked unchanged, all queries ran with `recordAccess: false`).
- CI: the `deps` job (dependency review) is skipped while the repository is private, because GitHub's dependency review needs Advanced Security on a private repository.
- CI: cargo-deny is pinned at 0.21.0 and zizmor at 1.32.0, because 0.22.0 and 1.33.x were younger than 7 days on 2026-11-25. cargo-deny 0.21.0 accepts every key of `deny.toml`.
- CI: added `Swatinem/rust-cache` (saves on `main` only), per-job timeouts, a concurrency group that cancels superseded pull request runs, and a nextest `ci` profile with `fail-fast = false`. None is in the spec; each keeps CI fast or its failures complete.
- Root files: `LICENSE` came from `gh api licenses/agpl-3.0` (gnu.org timed out from the build machine); the text is unmodified.
- Root files: `dependabot.yml` lists npm, uv and docker before their manifests exist (milestones 4, 6 and 8).
- Root files: `THIRD_PARTY_NOTICES` is generated by `scripts/third-party-notices.sh` at release and image build and is not committed (it is in `.gitignore`).
- nextest: the override that puts `stack_*` binaries in the one-thread test group is commented out until the first stack test exists (milestone 6), because nextest refuses a `binary()` filter that matches no binary.
- Repository name: the spec's placeholder `knoggin/knoggin` is written `knoggin-memory/knoggin`, the organization's real name, everywhere, including the workspace `repository` field.
- Crypto, signatures: `LocalKeyProvider::wrap`, `token::new_api_key` and `token::random_token` return `Result<_, KeyError>`, because the system random source can fail and nothing on a request path may panic.
- Crypto, container: `Header::expect` takes `(store, generation, sequence)` as plain values, because `knoggin_core::snapshot::SnapshotName` does not exist yet; a wrapper that takes the name can be added beside it.
- Crypto, container: `seal` returns the concrete iterator `Sealer` (with a `Debug` that prints counts), not `impl Iterator`. Added `read_header_from` (reads one header from a stream, for the server's streamed download) and `Header::check_content_format(min, max)`, because the content format range is a constant of `knoggin-core::snapshot`, not of the container.
- Crypto, container: `open` returns `TooLarge` only after the first chunk has verified the header, so an `out_of_memory` lock is never decided on an unverified `content_len`.
- Crypto, key set: parsing refuses unknown fields and a key whose ID is not the SHA-256 rule applied to its bytes.
- Crypto, keychain: every write is read back and compared, because `security -i` exits 0 even when its command failed (checked on macOS 26 against a keychain file that does not exist). `secret-tool lookup` that exits 1 with no output at all counts as "not found"; any other failure is an error.
- Crypto, keychain: the key file and keychain code live in `knoggin-crypto` (the tab "Workspace and crates" puts reading the key source in the binary); the binary keeps the `auto` choice and `key-source.json`.
- Crypto, key file: reading follows a link and checks the file it names; only writes refuse links, as the spec says.
